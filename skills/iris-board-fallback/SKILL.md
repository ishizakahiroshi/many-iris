# 看板が使えない間の引き継ぎ

## 入口を確かめる

看板への読み取りに失敗した時刻・対象案件・症状を控える。別の権限でしか見えない案件、権限不足、失効した鍵、明示的な全停止はその境界を守る。接続障害か判別できなければ「原因未確認」と記す。書き込みの応答だけが失われた場合は、処理結果を「不明」として照合から始める。

案件の相関番号と原本の参照から、同じ案件の既存の agent-board Issue と看板の項目 ID を特定する。両方へ書けるとは限らない。参照先、共有できる情報、署名する担当、送信の許可を現在の仕事から確かめる。書けない環境では控えを利用者に返す。

## 障害中に読む・記録する

| 看板で見たいこと | 代替先での扱い |
|---|---|
| 項目 | 案件番号に対応する既存 Issue を開き、看板の項目 ID と突き合わせる。 |
| 出来事 | 該当 Issue のコメントを時系列に読み、署名・対象・原本の参照を確認する。追記は下記の形を使う。 |
| 状態 | 案件で対応が決まっている既存ラベルを読み取る。書き換えるのはその案件の状態を変える許可と対応表がある場合だけ。対応が不明なら観測した事実をコメントに残す。 |

書き込みが認められている場合は、最初の記録に開始理由と最後に読めた看板の状態を添える。後続は同じ Issue の同じ障害記録に結ぶ。他の担当が開始を記録済みならその記録を使う。以下は架空の例。

```text
[看板経由ではない] 開始理由：看板の読み取りがタイムアウト
案件：EXAMPLE-1 ／ 看板項目：demo/task-1 ／ 観測時刻：2030-01-02T03:04Z
観測：原本に下書きが1件ある。看板での受理は不明。
Agent: demo
```

成果や次の指示は共有可能な原本への参照で示す。代替先のラベルやコメントで実行権、受理、完了を発行しない。看板の停止・世代・リースを確認できない間は、自動実行や結果不明の依頼の再送を保留する。

## 復旧時に突き合わせる

1. 一人の復旧担当を決める。対象案件の看板を正規の権限で読み、停止状態、項目 ID、現在の担当・依頼番号・世代を照合する。競合や世代の交代があれば記録を保留して現在の担当へ返す。
2. 障害中の各コメントの固定 URL を照合キーにする。看板の該当項目の出来事を読む。ページが省略されていたら、対象期間を覆うまで `board_list` の `next_since_seq` で続きを読む。照合済みのチェックポイントが無ければ対象案件の先頭から読む。読めない範囲があれば、その分を「不明」として残す。
3. 同じ参照が既にあれば、その出来事の番号を控える。未反映と確認でき、書き込みを許可された記録だけを、項目にメモとして戻す。通常の `board_add_event` では `kind=note`、`ref` に共有可能な固定 URL、`text` に出所と事実を渡す。実行中の担当に必要な依頼番号・世代、制限付き担当の許可範囲は通常運用と同じ。共有範囲の違う参照を複製しない。
4. 追記の応答を失ったら、同じ参照の有無をもう一度読み取る。メモの追記には自動の重複排除がない。受理・実行・完了やユーザーの承認を再生しない。
5. 案件 Issue に終了を記録する権限があれば、戻した出来事の番号、既反映分、未解決分と担当をまとめる。利用者にもこの3点を返す。
