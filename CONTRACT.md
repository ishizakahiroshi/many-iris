# Foundation integration contract

Standard-library Python 3.11+ package `prototype`. No external calls, real records or shell execution in the server. Fixtures synthetic. `python -m prototype.server --port 0 --db <new-local-file>`.

`prototype.engine.Engine(db_path)` owns SQLite state. Every method uses its own connection or otherwise guarantees thread safety. `seed_demo()` idempotently creates project `demo-project`, plan `demo-plan`, integer revision `1` and a second plan to prove scope. Demo work flows through a normal task, an approval-required task, and another normal task. A synthetic run can be paused, stopped, handed off and continued. Automatic ticks simulate execution, never launch an AI provider.

Methods: `snapshot()`, `document(document_id)`, `start(plan_id, revision, request_id)`, `tick(run_id=None)`, `decide(approval_id, decision, revision, request_id)`, `pause(run_id, request_id)`, `resume(run_id, request_id)`, `stop_agent(run_id, request_id)`, `handoff(run_id, request_id)`, `notifications(after=0)`. Inputs keyword arguments. `decide.decision` is `approve` or `reject`. Mutations return JSON dictionaries, request IDs bound to operation AND body (identical retry same response, changed payload conflict). No user-provided arbitrary paths, commands or URLs. `tick` chooses only active run(s); no external I/O. Stop_agent confirms synthetic stop; handoff forbidden if old status is merely unknown. Epoch/fencing rejects late old results through a separate documented engine method for testing. Unknown execution outcome cannot automatically retry a task.

`prototype.engine.DomainError` has `.code`, `.message`, `.status` (400/404/409), usable by HTTP layer. Safe fixed messages; no DB path disclosure. Conflicts handled server-side.

Snapshot keys: `synthetic: true`, `schema_version: 'many-iris-foundation/1'`, `projects`, `plans`, `tasks`, `runs`, `approvals`, `events`, `notifications`, `observed_at` ISO UTC. Arrays use dictionaries. All entities have `id`. Plans: `id,title,project_id,revision,task_ids`. Tasks: `id,title,plan_id,status,document_id,requires_approval`. Runs: `id,plan_id,status,agent_id,epoch,current_task_id`. Approvals: `id,run_id,task_id,revision,status`. Documents: `id,title,body,revision`. Notifications: `id,kind,created_at,body`; body generic (no project title, document or credentials). Events contain audit history. Plan/task IDs in UI come from actual snapshot; no hard-coded index mapping.

HTTP: GET `/api/snapshot`; GET `/api/documents/<id>`; GET `/api/notifications?after=<integer>`; POST `/api/actions` JSON `{action,request_id,...}`. Actions `start,tick,decide,pause,resume,stop_agent,handoff`. `tick` is test/demo-only. POST requires application/json and exact local Origin if provided. Bind only 127.0.0.1; exact Host with actual port; reject unknown origin/host. Limit bodies, reject malformed UTF8/JSON, duplicate keys and nonfinite numbers. No CORS grants. GET static allowlist only; no path traversal. Background tick simulates autonomous fake work with no network execution. UI clearly labels synthetic and local. Non-loopback devices unsupported in this candidate.

Owners: core agent engine.py + store.py + tests/test_engine.py; UI agent server.py + web/* + tests/test_http.py; root __init__.py, adapter/notification contracts, packaging, README, integration tests and integration. Do not modify another owner's files. Core tests use temporary DBs; HTTP tests use a controlled stub engine if core unavailable. Candidate source imports never read personal configuration. No installation, build, real AI, external send, push or main changes. Worktree branch commits allowed; root integrates.
