# VPS中継ハブとローカル並列を組み合わせた運用の設計記録

低スペックVPSをCLI専用の直列バッチ中継ハブに限定し、重い実装・並列処理は
ローカルPC側ワーカーで実行する構成（Issue #41）の、確認済みの設計を記録する
ものです。2026-11-22に持ち主と1項目ずつ確認しました。

> **2026-11-22 追記（#46 の決定）**: 方針 6 は廃止した。振り分けは、案件ごとの
> 「ローカルだけ／どこでもよい」の設定と持ち主の順番で決め、ローカルとクラウドは
> 同時に別の仕事を進める。ローカルのワーカーは VPS と同じ `picker/` を使い、
> many-ai-cli にセッションを起動させる。そのほかの方針（1〜5・7・8）はそのまま。

## 目的

低スペックVPSをCLI専用の直列バッチ中継ハブに限定し、重い実装・並列処理は
ローカルPC側ワーカーで実行する構成を整備する。

## アーキテクチャ

- 操作端末: スマホ／既存PCブラウザ、Cloudflare Access経由の `/board`
- オーケストレーター: Many Iris board-worker、Cloudflare Workers / Access
- VPS中継ハブ: CLI専用、`picker/`によるポーリング、直列または1〜2並列のバッチ
- 実働層: ローカルPCのClaude Code / Codex等、約30セッション規模の並列実行

## 確認済みの実装方針（8件）

1. **VPSにGUI・Xvfbを載せない** — VPSはCLI専用とする。
2. **VPS側の同時実行数を1〜2並列、基本は直列に制限する** — 低スペックVPSが
   詰まらないよう、基本は直列で、多くても1〜2並列までとする。
3. **スワップを確保し、OOM対策を行う — 2GBで始める** — Issue本文は2〜4GB
   だが、確認のうえ2GBで始めることにした。VPSのメモリは1GBで、2GBの
   スワップは定番の組み合わせである。OOMが出るようなら4GBに増やす。
   4GBにしても害はないが、ディスクを4GB食ううえ、スワップを多用し出すと
   ディスクが遅くてほぼ止まるため、OOMの根本対策にはならない。
   swappinessは低めにし、緊急用だけに使う。スワップの確保はOOM対策の
   一部であり、並列数の制限（上記2）とセットで考える。
4. **ローカルPC側のポート開放を行わない** — ローカルPCは外から開けず、
   ワーカーがVPSからジョブを取りに行く形にする。
5. **ローカルワーカーがVPSからジョブを取得するアウトバウンド方式にする** —
   VPSからローカルへ押し込むのではなく、ローカルワーカーがVPS／boardへ
   取りに行く。ポート開放なしで動く形である。
6. **（2026-11-22 廃止）~~ローカルPCのスリープ・オフライン時のみ、VPS軽量バッチまたはDevinへ
   フォールバックする~~** — 代わりに、案件ごとに「ローカルだけ」「どこでもよい」を
   設定し、その範囲で持ち主の順番の先頭の、動いている拾い手へ渡す（#46 の 6）。
   手元にしか置けない資料が要る案件は「ローカルだけ」にする。
7. **同一リポジトリの並列作業には `git worktree` を使う** — 同じリポジトリを
   複数のセッションで並行して触るときは、ブランチごとにworktreeを分けて
   作業する。
8. **タスクの世代管理・リース期限・二重実行防止を検証する** — 同じタスクを
   2人が二重に取らないよう、世代や期限付きのリースで管理する仕組みを
   確かめる。

## 検討事項（6件、方向を確認済み）

1. **ジョブの優先度、タイムアウト、リトライ、死活監視** — どのジョブを先に
   やるか、どれくらいで諦めるか、失敗したら何回やり直すか、ワーカーが
   生きているかどう見るか、を決める。
2. **ローカルワーカーの登録、認証、切断時の再接続** — ローカルワーカーを
   どう登録して、どう認証して、切れたらどうつなぎ直すかを決める。
3. **30セッション同時実行時のCPU・メモリ・ディスク・APIレート制限** —
   ローカルで約30セッションを同時に動かすとき、CPUやメモリ、ディスク、
   APIの制限にぶつからないかを見る。メモリについては、ローカルPCは
   約80GB積んでいるため問題ない（1セッション2GBとしても30セッションで
   60GBに収まる計算）。CPU・ディスク・APIレート制限は別途見る必要がある。
4. **worktreeの作成・削除・残骸掃除の自動化** — worktreeを作って、使い
   終わったら消して、残ったゴミを自動で掃除する仕組みを決める。
5. **VPSとローカルの役割境界をドキュメント化する** — VPSがやることと
   ローカルがやることの線引きを文書に残す。本ファイルがその一部である。
6. **障害時のフォールバック順序と通知** — 障害が起きたらどの順番で
   切り替えるか、誰にどう知らせるかを決める。
