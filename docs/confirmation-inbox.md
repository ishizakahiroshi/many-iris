# Irisで作業の確認を受け取る

Irisの看板を開くと「確認待ち」に、依頼元・案件・作業・質問が並びます。「許可」はその行の質問への1回の回答です。あとで判断する仕事は、そのまま一覧に残せます。「許可済み・受取待ち」は、本人が回答し、依頼元から適用結果がまだ届いていない状態です。

## Claude Desktopやターミナルから接続する

共通の入口は既存のリモートMCPサーバー `https://<Irisのホスト>/board/mcp` です。MANY-AI-CLIの起動は不要です。

- **Claude Desktop** ではカスタムコネクタに自分のIrisのMCP URLを登録し、本人のアカウントで接続します。リモートコネクタの通信はClaudeのクラウドから届きます。[Claudeの接続手順](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)
- **Claude Code** では、次のコマンドのURLを置き換えて接続先を登録し、セッションで `/mcp` を開いて認証します。他のCLIは各製品のリモートMCPクライアント設定を使います。[Claude CodeのMCP設定](https://code.claude.com/docs/en/mcp)

```sh
claude mcp add --transport http iris https://iris.example.com/board/mcp
```

クライアントに「作業の判断が必要なとき、この案件・作業名と具体的な質問をIrisの確認待ちに置いて。回答を確認するまで作業を保留して」と伝えます。MCP呼び出しは短時間で返ります。次の呼び出しを誰が起動するかはクライアント側で決まります。継続実行できるクライアントは待機中に状態を確認でき、会話が終了するクライアントは次のターンで同じ依頼IDを確認できます。端末が画面に出すアプリ固有の権限確認には、引き続きそのアプリの操作が必要です。

## クライアントからの1往復

| 順番 | 操作 | クライアントの扱い |
|---|---|---|
| 1 | 新しい質問ごとにランダムな小文字16進32桁の `request_id` を生成 | 同じ作業で通信をやり直す間だけ同じIDを使う |
| 2 | `iris_request_confirmation` にIDと `project`・`agent`・`task`・`question` を渡す | 本人が対象と操作を判断できる質問を1件だけ送る。ログ・鍵・会話全文は含めない |
| 3 | 本人がIrisの画面で許可。依頼元は同じ資格情報とIDで `iris_confirmation_status` を読む | `pending` なら待機。`approved` なら元の作業がまだ同じ質問を待っているか調べる |
| 4 | 同じ質問に1回だけ回答を適用し、`iris_close_confirmation` にIDと `outcome: "applied"` を渡す | 先に終了・変更された質問は `expired`。適用結果が不明なら `unknown` と報告し、自動再実行を止める |

同じ文章の質問を後でもう一度出す場合も、新しいIDを使います。公開する情報だけでは安全に判断できない場合は `local_only: true` とし、「元の画面で確認」を表示できます。依頼元の識別はサーバーが認証情報から行います。別の端末・担当との鍵の共用は避け、ひとつの処理中は接続元を維持してください。

既存のOAuth接続で確認用の接続情報が足りないと表示された場合は、コネクタを再認証します。送信元はOAuthで許可した接続単位、または発行した書き手キー単位です。案件名・AI名・質問は依頼元から届いた表示内容です。

「全部止める」の間は許可と新しい許可の受け渡しを休止します。24時間回答されなかった質問は失効します。許可後24時間たっても適用報告が届かないと「適用結果不明」となります。再実行の前に元の仕事の状態を確認してください。
