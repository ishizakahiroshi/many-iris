# 受付前の巡回表示

看板の依頼カードと `board_request_status` の `poll` は、同じ巡回の記録を参照します。受理後はこれまでの工程や結果に移ります。見送りが報告されていれば見送りを優先し、保留・所有者判断待ち・担当未決定には巡回を表示しません。

`poll` は `null` または `{assignee,last_poll_at,next_poll_at,next_poll_source,overdue}`。時刻はミリ秒の Unix 時刻、未確認は `null` です。看板の差分応答にも `poll_by_queue` が含まれ、キーは `JSON.stringify([assignee, project])` です。

- 最終巡回：認証済み担当が `board_my_work` で該当案件または全案件の受付キューを最後に確認した時刻。新着ゼロも含みます。ボードが一時停止中の照会、状態照会、受理、heartbeat、古い `board_list` の代替読取は含みません。この時刻は担当者が依頼を受理したことや、個々のカードを読んだことを示しません。
- 次回目安：運用者が `BOARD_POLL_INTERVALS` に登録した担当ごとの秒数（例：合成担当の `{"example-picker":600}`）。登録間隔と最終実績がある場合だけ加算し、`next_poll_source` は `configured_interval_estimate` です。スケジューラーの確定予定ではありません。未設定・初回巡回前・手動の担当については予定を推測しません。設定は最大64人、60〜86400秒の整数。無効な設定は目安なしとして扱います。
- 目安を2分より長く過ぎた場合は「巡回を確認できていません」と表示します（目安＋2分を超えた時点で `overdue`）。停止や失敗は断定しません。

この機能は起動・通知・スケジュールの変更を行いません。予定の表示だけで手動担当を自動受付に変えることもありません。
