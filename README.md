# Many Iris

自分の開発の進み具合を、AI の作業と合わせて一か所で見渡すための個人用 OSS です。作者が自分で使う範囲で作っています。一般向けの設定不要なサービスや、すべての AI への対応を約束するものではありません。

## いまあるもの

| 場所 | 中身 | 状態 |
|---|---|---|
| `board-worker/` | 進捗の看板。Cloudflare Workers で動き、保存は SQLite 型の Durable Object | 作者の環境で稼働中 |
| `iris/` | 計画と実行の参照実装（Rust）。手元の PC だけで動く | 2026-11-22 に凍結（#46）。今の状態の正本は看板で、ここには新しい機能を足さない。合成データと合成の担当だけで動く。詳しくは [`iris/README.md`](iris/README.md) |
| `prototype/`・`tests/`・`examples/`・`CONTRACT.md` | 最初に作った Python の試作 | 記録として残している。新しい機能は足さない |
| `experiments/stack-evaluation/` | 本体の言語を決めたときの比較（Python・Go・Rust） | 記録 |

## 看板（board-worker）

案件・計画・Issue・PR・作業を項目として並べ、それぞれに「始めた」「終わった」「メモ」などの出来事を書き足していく看板です。

「表示」でカード・1行一覧・実績ガントを切り替えられます。一覧では進行中・予定・待ちが先に並び、完了・停止は下の区画にまとまります。日付欄の●は日本時間で記録がある日です。前後の週や指定日にも移動できます。

実績ガントでは、作成・再開から完了・停止までを棒で表示します。継続中の棒は確認日まで伸び、終了日の記録がない項目には「終了日不明」と表示します。行や棒を選ぶと詳細・操作・実績日の内訳を開けます。一覧とガントを切り替えても同じ項目を参照できます。

看板を読み取れない間の記録先と、復旧後の照合手順は[看板障害時の引き継ぎスキル](skills/iris-board-fallback/SKILL.md)にあります。

項目の基本は次のとおりです。

- 項目には種類が 6 つあります：案件（`project`）・計画（`plan`）・文脈（`context`）・Issue（`issue`）・PR（`pr`）・作業（`task`）。
- 項目は、どれか 1 つの案件（`project` に書く名前）に属します。画面は案件ごとに分けて表示します。
- 項目には親を 1 つ付けられます（同じ案件の項目だけ。6 段まで）。たとえば、案件の下に計画、計画の下に作業を置きます。親を付けていない項目は、木のいちばん上に並びます。
- 状態は 5 つです：予定（`planned`）・進行中（`in_progress`）・待ち（`waiting`）・完了（`done`）・停止（`stopped`）。
- 項目は 5,000 件、出来事は 50,000 件まで。項目や出来事を消す道具はありません。
- 使える文字や長さなどの細かい決まりは、Rust 版の看板と同じです。全部の決まりは [`iris/README.md`](iris/README.md) の「看板（board）」にあります。

読み方と書き方は次のとおりです。

- 人は、ブラウザで `/board` を開いて読みます。入口は Cloudflare Access で、許可したメールアドレスの人だけが入れます。Worker も Access の署名を自分で確かめます。
- VPS の Claude・Devin が受けた仕事のカードには「話す」が出ます。押すとスマホ向けのチャットが開き、書いて「送る」と、その相手が 1 分以内に拾って、最近のやり取りと同じ branch を元に続きをやり、返事を書きます（1 往復 30 秒〜1 分ほど）。作業役に渡す履歴は新しい側から約 12 万字です。古いやり取りが省略されると「判断待ち」になり、持ち主が元の会話を確認して今回の指示と必要な承認を送り直すまで起動しません。再開する作業役には、省略の印・元の会話・最近の成果リンクも渡ります。ファイルを変えたときは同じ Draft PR に積み増します。途中で相手（Claude と Devin）を替えても続きから進みます。会話は看板のふだんの記録とは別に置き、1 件 20,000 字まで書けます。長い文章（2,000 字超の貼り付け）・テキストファイル（.txt .md .log、1 MB まで）・画像（スクショの貼り付け・ドロップ・＋。PNG・JPEG・WebP・GIF、5 MB まで）は添付として Cloudflare R2 に置き、30 日で消えます（1 つの会話で 20 MiB まで）。相手には目印だけを渡し、拾い手が添付をファイルにして作業役へ渡します。送れるのはログインした持ち主だけで、回数の上限はありません（2026-11-21 の作者の判断）。「仕事を積む」の「話して頼む」は、積んで任せてそのまま会話を開きます。
- 看板のいちばん上で、案件を選ぶとその案件だけを表示できます（選んだ案件は端末が覚えます）。「番号で探す」に依頼の番号（`REQ-…`）や項目の名前・題名の一部を入れると、その案件に切り替えて、見つかった項目に枠を付けます。
- 看板の持ち主は、同じ画面から 6 つのことができます。「仕事を積む」（題名を書いて、予定の作業を 1 つ足す）、「入れる先を変える」（作業を、別の項目の下へ付け替える・どこにも入れない状態に戻す）、「上へ・下へ」（同じ項目の下に積んである作業の順番を変える）、「任せる」（積んである作業に依頼の番号と行き先を付けて、AI が受けるのを待つ。まだ誰も受けていない間は「行き先を変える」で付け直せ、「取り下げる」で戻せる。行き先は下の「任せた作業の振り分け」）、「続きを任せる」（手元の PC で止まったセッションの項目 `session/<番号>` に出る。その下に「session/<番号> の続き」という作業を作って、選んだ行き先へそのまま任せる。行き先の既定は VPS。続きは 1 つのセッションに同時に 1 つまで。拾う側の読み方は `docs/ipad-picker.md` の「巻き取り」）、「おまかせの順番」（看板のいちばん上の 1 行。「変える」で、行き先を付けずに任せた仕事をどの相手から順に当てるかを、上へ・下へと「おまかせで使う」の印で決める。押した時点で保存される）です。順番は持ち主だけのもので、AI の道具からは変えられません。題名や状態を直すこと、計画を動かすこと、消すことは、画面からはできません。画面から書いたものは、書いた人が `page:owner` と記録されます。
- AI や道具は、`/board/mcp`（MCP）へ書きます。道具は `board_upsert_item`（項目の作成と更新）・`board_add_event`（出来事の追加）・`board_list`（読み取り）・`board_my_work`（自分宛ての分だけを読む。受けられる仕事・自分の実行・自分宛ての会話の数・「手元だけ」の案件・「全部止める」中かどうか。拾い手が定期的に見るのはこちらで、`board_list` より読む量がずっと少ない）・`board_request_status`（読み取り専用。依頼が「保存しただけ」「依頼済み」「受付済み」「実行中」「連絡途絶」「不明」「完了」のどこにあるかを、根拠・確認できていないこと・停滞・成果物リンクと一緒に返す。何も書かず何も起動しないので、状況を聞いても二重実行にならない。開いている GitHub の Issue は根拠にしない）・`board_request_handoff`（積んである作業を任せる。画面の「任せる」と同じで、行き先 `to` を付けられる）・`board_accept_handoff`（任された作業を、依頼の番号を添えて受ける。受けられるのは最初の 1 つだけで、行き先が付いていればその名前の書き手だけ）・`board_route_handoff`（まだ誰も受けていない依頼の行き先を変える。画面の「行き先を変える」と同じ）・`board_take_back_handoff`（まだ誰も受けていない依頼を取り下げる。画面の「取り下げ」と同じ）に、受けた後の実行を守る 7 つ——`board_heartbeat_handoff`（まだ作業中だと伝えて連絡の期限を延ばす）・`board_progress_handoff`（世代で守られた進捗の書き込み）・`board_complete_handoff`（世代で守られた完了）・`board_mark_handoff_unknown`（連絡が途絶えた実行を状態不明にする）・`board_release_handoff`（仕事を積み直す）・`board_resume_handoff`（状態不明から同じ実行で続ける）・`board_resolve_dispatch`（起動したかどうか分からなくなった Devin の起動を、人が確認して後始末する）——を足した 16 個と、会話（「話す」）のための 4 つ——`board_chat_pending`（自分宛ての会話の順番を古い順に見る。VPS の Claude・Devin だけ）・`board_chat_take`（1 つを受けて、それまでのやり取りをもらう）・`board_chat_reply`（20,000 字までで返事を書く）・`board_chat_attachment`（添付を読む。文字は少しずつ、画像はそのまま返す）——の 20 個です。受けた担当者本人の `board_upsert_item` / `board_add_event` には世代の提示が要ります（他の書き手は従来どおり）。詳しくは [`docs/ipad-cloud-resume.md`](docs/ipad-cloud-resume.md) を見てください。
- AI や道具の本人確認は、使う場面で 2 通りに分かれます。手元のスクリプトや CLI から書くときは、書き込み用の鍵を `Authorization: Bearer <鍵>` で送ります。ChatGPT のように鍵を送れない MCP の client は、OAuth で接続します。OAuth の許可の画面（`/authorize`）は、Access でログインした看板の持ち主だけが開けます。OAuth の部分は Cloudflare の [`@cloudflare/workers-oauth-provider`](https://github.com/cloudflare/workers-oauth-provider) を使っています。
- 書いた人は、鍵か、許可した client から決まります。本文で名乗ることはできません。
- 作業（種類 `task`）のうち親の無いものは、画面では案件ごとの「まだ結ばれていない作業」にまとまります。既にある項目の親は、後から付けられます（AI からは `board_upsert_item` に `item_id` と `parent_id` だけを送る。持ち主は画面の「入れる先を変える」）。先に作業を記録し、あとで計画の下へ付け替える使い方ができます。
- 受けた実行には、世代（`handoff.generation`）と連絡の期限（`handoff.lease_until`、30 分）が付きます。実行はハートビートで期限を延ばし、進捗と完了は世代を添えて書きます。世代の違う古い実行の書き込みは `STALE_GENERATION` で断られます。受理の応答が届かなかったときは、同じ担当が同じ番号でもう一度受けても同じ受理が返ります（二重に走りません）。期限が切れても自動では何も起きません。持ち主が担当の状態を確かめて、画面か道具で「状態不明」にすると、その仕事は勝手に再実行されずに隔離され、停止を確認したときだけ積み直せます（まだ作業中と確認できれば、同じ実行のまま続けられます）。
- 作業には、画面でもう 1 つ札が付きます。予定のままの作業は「積んである」、任せて誰も受けていない作業は「任せた・まだ受けていない」（行き先が保留なら「任せた・保留中」）、受けられた作業は「任せた・受けた」、それ以外は「記録だけ」です。

### 任せた作業の振り分け

任せた作業には、行き先が付きます。行き先は「道具 × 動く場所」で 9 つです：`vps-claude`（VPS の claude -p）・`local-claude`（手元 PC の claude -p）・`devin`（Devin、クラウド。看板がセッションを起こす）・`vps-devin`（Devin、VPS）・`local-devin`（Devin、手元 PC）・`muse`（Muse）・`grokbot`（GrokBot）・`owner`（自分）・`hold`（保留）。Devin を動く場所で分けたのは 2026-11-21 の作者の判断です（VPS に入れた Devin を看板から呼べるようにするため）。

- 行き先を付けた依頼は、その名前の書き手（鍵の `actor`）だけが受けられます。`owner` と `hold` は誰も受けられず、行き先が付け直されるか、取り下げられるのを待ちます。違う相手が拾う事故を、仕組みで起こさないためです。
- 行き先は、持ち主が画面の「行き先を変える」で、書き手が `board_route_handoff` で付け直せます（2026-11-14 の作者の判断。画面を開かずに AI へ頼めるようにするため）。書き手は、保留の作業を自分宛てに付け替えて受けることもできます。誰が付け替えたかは、出来事に「routed … to …」として書き手の名前つきで残ります。
- 行き先を付けずに任せる（おまかせ）と、看板が持ち主の決めた順番を上から見て、いま拾っている最初の相手へ渡します。だれも拾っていなければ `hold` にします（2026-11-21 の作者の判断。題名を AI に読ませて選ぶ形をやめ、保留で朝まで止まるより誰かが受けて「できない」と返すほうを選んだ）。持ち主が画面で「任せる」「続きを任せる」「行き先を変える」「おまかせの順番」を押したときはその場で、それ以外（AI の道具から任せたとき）は 10 分ごとの cron で決まります。「拾っている」は、その相手の鍵が看板へ最後に来てから 15 分以内のことです（VPS は 1 分ごと、手元 PC は 5 分ごとに来る）。`devin`（クラウド）は看板が起こすので、`DEVIN_API_KEY` があれば拾っている扱いです。順番の既定は VPS → 手元 PC → Devin（クラウド）で、`owner` と `hold` は順番に入れられません（`hold` はいつも最後）。選んだ結果は、出来事に「routed to vps-claude: number 1 in the owner's order」のように、何番目だったかと飛ばした相手つきで残ります。
- 「全部止める」（看板の上。持ち主だけが押せる）を押すと、再開するまで、新しい仕事も会話も受け付けず（受けようとすると `PAUSED`）、Devin も起動せず、拾い手を起こしません。動いている仕事には、次の連絡（`board_heartbeat_handoff` と `board_progress_handoff` の答え）で `stop: true` が返り、拾い手はその実行を止めて仕事を積み直します（再開したら、持ち主がもう一度任せる）。看板そのものが止まっているときの保険は、これまでどおり拾い手の STOP ファイルです（#46 の Q7、2026-11-22）。
- 案件ごとに「範囲」を決められます（案件の名前の下の「範囲」）。「手元だけ」にした案件の仕事は、手元の PC の書き手（`local-*`）だけが受けます。VPS・Devin・Muse などへの行き先は断られ、おまかせは順番のうち手元の相手だけを見ます。手元だけにした時点で外へ向いていた未受付の依頼は、おまかせに戻ります。サーバーの AI とも話せません。既定は「どこでもよい」です（#46 の Q6、2026-11-22。private のリポジトリの案件は手元だけにする）。
- 受けた書き手は、使っている版（拾い手・決まり・Skills の commit）を `board_accept_handoff` の `versions` で伝えられ、看板は依頼と受けた出来事に残します。終えた実行は `board_complete_handoff` の `ref`（PR などの https のリンク）と `commit` で結果を残せ、カードに「結果」として出ます（#46 の Q8・段 2）。
- 依頼には、誰が任せたか（`handoff.requested_by`。画面からなら `page:owner`、MCP からなら書き手の名前）、今の行き先を誰が決めたか（`handoff.to_set_by`。持ち主が任せた仕事を持ち主の順番で渡したときは `page:owner`、保留にしたときと書き手が任せた仕事は `dispatcher`）、任せた時点の題名（`handoff.title`）が残ります。後から題名が書き換えられても、任せた時点の題名は変わりません。人の見ていない所で作業を始める拾い手は、これを見て「持ち主が任せ、持ち主が行き先を決めた依頼」だけを動かせます。
- 行き先が `devin` の依頼だけ、同じ処理（画面で押した直後と、10 分ごとの cron）が Devin のセッションを起こします（秘密 `DEVIN_API_KEY` があるときだけ。1 件につき 2 回・1 日 6 回まで）。起こす前に看板へ予約を書くので、同じ依頼を 2 つ起こすことはありません。Devin の応答が届かなかったときは、起きたかどうか分からないので自動では起こし直さず、人が Devin の側を見て `board_resolve_dispatch` で片付けます。Devin が断ったとき（鍵の誤りなどの 4xx）は、起きていないことが確かなので、人の片付けは要りません（回数には数えます）。それ以外の行き先は、その相手が自分で拾います（拾う側として `picker/` があります。看板の fenced ツールを使うため、この節の受理とリースの仕組みが前提です）。

### 自分の Cloudflare に置く

Cloudflare のアカウントと、Cloudflare で管理しているドメインが要ります。以下は `board.example.com` に置く例です。

1. `board-worker/` で依存を入れます（`pnpm install`）。
2. `wrangler.toml` の `routes` の `pattern` と `BOARD_PUBLIC_ORIGIN` を、自分のドメインに書き換えます。OAuth の保存先の KV を作り（`wrangler kv namespace create <名前>`）、出てきた id を `[[kv_namespaces]]` の `id` に書きます。
3. Cloudflare Zero Trust で、Access のアプリを 2 つ作ります。
   - `board.example.com` 全体：自分のメールアドレスだけを許可する（`/authorize` もここに入る）
   - `board.example.com/board/mcp`・`board.example.com/.well-known/*`・`board.example.com/oauth/*`：Bypass（MCP は Worker が鍵か OAuth の token で確かめ、OAuth の発見と token の受け渡しは client が直接呼ぶため）
4. 書き込み用の鍵を作ります。鍵は新しいファイルに書かれ、画面には出ません。一覧には鍵の SHA-256 だけが入ります。

   ```powershell
   node scripts/new-key.mjs --list <keys.json> --actor <書く人の名前> --key-out <鍵のファイル>
   ```

5. 秘密を 4 つ登録します（`wrangler secret put <名前>`）。
   - `BOARD_WRITERS`：手順 4 の一覧（鍵の SHA-256 だけ）
   - `ACCESS_TEAM_DOMAIN`：`https://<team>.cloudflareaccess.com`
   - `ACCESS_AUD`：手順 3 で作った全体用のアプリの Application Audience（AUD）タグ
   - `BOARD_OWNERS`：看板を読める人のメールアドレス（カンマ区切り）
   - 任意で `DEVIN_API_KEY`：行き先 `devin` の依頼で Devin を起こすときだけ
6. `wrangler deploy` で配置します。`workers.dev` とプレビューの住所は、`wrangler.toml` で切ってあります。

鍵のファイルと `<keys.json>` は、リポジトリの外に置いてください。

あとから書く人を足すときは、手順 4 を同じ一覧に対して繰り返し、一覧を wrangler secret put BOARD_WRITERS で上げ直します。一覧のファイルを変えただけでは、看板に効きません。

### 試験

`board-worker/` で `pnpm test` を実行します。先に `test/route.test.mjs` が、振り分けと cron の判断（持ち主の順番の読み方・拾っているかの見分け・Devin を起こす条件）を、看板・Devin の代役で Node の上だけで確かめます。続けて `test/board.test.mjs` が、`wrangler dev`（手元の workerd）の上で、鍵の拒否・Access の署名の確認・OAuth の一周（発見・client の登録・許可の画面・PKCE・token・使い回した code の取り消し）・項目と出来事の規則・持ち主が画面から書く操作（ほかのサイトからの要求の拒否を含む）・上限・再起動後も残ることを確かめます。一時フォルダは OS の一時フォルダ（`BOARD_TEST_TEMP` で変えられます）に作り、終わると消します。

## 参照実装（iris）

計画と許可、判断待ち、実行の状態、成果の根拠を一つの流れで確かめる、手元専用の参照実装です。2026-11-22 に凍結しました（#46）。今の状態の正本は看板（`board-worker/`）で、ここには新しい機能を足しません。起動の仕方・MCP・看板・状態の診断と復旧は [`iris/README.md`](iris/README.md) にまとめています。試験は `iris/` で `cargo test --locked` を実行します。
